# 安全启动与 TPM 审计

审计的对象是**这台机器信任什么**，不是"有没有 TPM 这个硬件"。
TPM 只负责记录（度量），信任谁由四个变量决定，两者要分开说。

## 第一步：一次读全

`dump_tpm`，参数 `{}`

它一次给出两半：

- **TPM 那一半**：固件有没有发布 TCG2、TPM 在不在、活跃 PCR bank、事件日志格式。
- **信任库那一半**：`SecureBoot` 与 `SetupMode` 的值，`PK`/`KEK`/`db`/`dbx`
  四个变量在不在、各多少字节。

**先读结论那一行**，再看细节。工具自己已经按组合给了判断，你要做的是核对
它引用的证据，而不是重算一遍。

## 四个变量各是什么

| 变量 | 作用 | 空着意味着 |
|---|---|---|
| `PK` | 平台密钥，**唯一能改信任库的钥匙** | 机器在 Setup Mode，谁都能接管 |
| `KEK` | 密钥交换密钥，用来更新 db/dbx | 无法在不进固件界面的情况下更新信任库 |
| `db` | 允许启动的签名库（证书或哈希） | 什么都不被信任，开了安全启动也起不来 |
| `dbx` | 禁止启动的签名库（吊销名单） | 没有吊销名单，已知有问题的引导器仍可运行 |

**只看字节数**：`PK: 1184 byte(s)` 说明装了证书，`PK: absent` 说明没有。
工具不打印内容，因为那是一个证书；**你也不能推断里面是哪家厂商的证书**。

## 三种组合的结论，差别很大

1. **`SetupMode = 1` 且 `PK: absent`**
   出厂状态。安全启动关着，任何人都能把自签名证书写进去。
   结论要写成"这台机器现在不设防"，不要说成"安全启动坏了"。

2. **`SecureBoot = 1` 且 `SetupMode = 0`**
   正在执行。不在 `db` 里、或在 `dbx` 里的引导器会被拒绝。
   这是"能不能装第三方系统"这个问题唯一的否定答案。

3. **`SecureBoot = 0` 但 `PK` 有内容**
   最容易被误读的一种：**密钥装了，检查没开**。看起来"配置好了"，
   实际什么都不拦。必须明说"密钥在，但没有生效"。

4. **`SecureBoot` 与 `SetupMode` 同时为 1**
   固件自相矛盾。直接说"这台固件的安全启动状态不可信"，
   不要挑一个当真。

5. **`SecureBoot: absent` / `SetupMode: absent`**
   固件根本没实现安全启动。这和"关着"是两件事：
   一个是没有这个功能，一个是功能在但停用了。**不要合并成一句"没开"**。

## 第二步：只在需要时交叉验证

`read_env`，参数 `{"name":"Secure"}` 与 `{"name":"SetupMode"}`

`dump_tpm` 已经读过这两个值。**只有当它的输出和用户的描述冲突时**才用
`read_env` 复核（比如用户说"我明明开了安全启动"）。两个工具读的是同一份
变量，复核只能确认"值确实是这个"，不能解释为什么。

## 第三步：TPM 不等于安全启动

如果 `dump_tpm` 说 `TPM interface: none`：

- 安全启动**仍然可以工作**（它只依赖那四个变量）；
- 但**度量启动不可用**：没有 PCR 被扩展，启动链没有可验证的记录；
- 结论里要写清这一点，不要让用户以为"没有 TPM 就等于没有安全启动"。

反过来，TPM 在也不代表安全启动生效——这是两套机制。

## 不要做的三件事

- **不要声称 `db` 里有某个厂商的证书。** 工具只给字节数，看不到内容。
  用户问"微软的证书在不在"时，答案是"看不到，只能看到信任库非空"。
- **不要因为 `dbx` 非空就说"某个引导器被吊销了"。** 同样看不到内容。
- **不要用常识补洞。** 变量不存在、工具报不支持，都是结论的一部分。

## 输出格式

### 硬件与固件
有没有 TPM、TCG2 版本、活跃 PCR bank、事件日志——一句话。

### 信任库
`SecureBoot`、`SetupMode` 的值，以及 PK/KEK/db/dbx 各自在不在、多大。

### 结论
两三句：这台机器现在**拦不拦**、**谁能改**、**缺什么**。

### 下一步
一条可执行的建议：进固件开安全启动 / 先装 PK / 更新 dbx / 什么都不用做。

## 什么时候承认不知道

问的是"这个具体驱动/系统能不能装"时，答案取决于它的签名和 `db` 的内容，
而 biosllm 看不到 `db` 里面。**直接说"信任库非空，但我看不到里面是哪张证书，
所以无法判断这个镜像会不会被接受"**，不要猜。
