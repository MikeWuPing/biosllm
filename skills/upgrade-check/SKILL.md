# 能不能升级

答案在**固件自己写的上限**里，不在你记住的型号参数里。三件事分开问：
**现在装了什么**、**板子允许到什么程度**、**这两者之间还剩多少**。

## 步骤

1. `dump_smbios`，参数 `{"type":16}` —— 内存阵列：`max capacity` 是电气上限，
   `slots` 是插槽总数。
2. `dump_smbios`，参数 `{"type":17}` —— 已装内存条：每条的 `size` 与 `slot`。
3. `dump_smbios`，参数 `{"type":4}` —— 处理器：`socket`、`upgrade`（板子接受什么）、
   核心/线程。
4. `dump_smbios`，参数 `{"type":9}` —— 插槽：`type`（PCIe 代数）、`data width`、
   `usage`（`available` 才是空着的）。
5. 需要时 `cpuid` —— 缓存、频率、VT-x。

结构多时先看顶部的类型清单，再用 `{"type":N}` 单独取。**没有你要的类型就说没有**，
不要拿别的类型凑。

## 三个不许混淆

**上限 ≠ 建议。** `max capacity` 是电气与寻址的上限，不是"你应该装这么多"。
报"最多支持 128 GB，现在 16 GB"就够，不要加"建议加到 64 GB"——那是配置建议，
依据不在固件里。

**空槽 ≠ 支持。** `usage: available` 只说明槽是空的。装得进去不等于点得亮：
内存要看代际（DDR4 槽不认 DDR5）与厂商 QVL，CPU 要看芯片组与 BIOS 微码支持，
显卡要看供电与长度。**这些固件都不告诉你**，直说"看不到"。

**socket ≠ 兼容清单。** `socket: LGA1700` 只说明针脚。同插槽跨两代不认、
需要新 BIOS 微码、OEM 锁 CPU——都可能。**不要列出"你可以换成 i9-14900K"这种话**，
除非固件里 `upgrade` 字段明确写了支持的处理器家族，而它通常只写插槽类型。

## 输出格式

### 现状
每一项一行，带来源：`内存 16 GB（2 × 8 GB，DDR4-3200，A1/B1 槽）`。

### 还能加什么
- 内存：`上限 128 GB，已装 16 GB，4 个槽用了 2 个 → 还有 2 个空槽，还能加 112 GB`
  （上限未知就写未知，不要用"通常"补）
- 插槽：`PCIe 4.0 x16 一个（空闲）、PCIe 3.0 x1 两个（一个占用）`

### 我看不到的
一句话列清楚：具体型号的兼容性（QVL）、供电与尺寸、芯片组对某代 CPU 的支持。
**这一段不能省**——省了就成了"能装"的承诺。

## 什么时候承认不知道

`dump_smbios` 报某个类型不存在（很多机器不发布 Type 9）——直接说"这台固件没有
报告插槽信息"，不要从 PCI 设备树反推插槽数量，那两件事不一样。
