# 硬件报告

按下面的顺序取数据。**每一项都来自工具，不要凭型号猜**。取不到的项写"不可用"，
不要编造——这份报告的价值全在于它是这台机器的实测结果。

## 步骤

1. `dump_smbios` —— 厂商、型号、BIOS 版本、内存条（SMBIOS 是机器自述身份的地方）
2. `cpuid` —— CPU 厂商与型号字符串
3. `dump_memmap` —— 总内存容量
4. `dump_pci` —— 总线上的设备
5. `dump_acpi` —— ACPI 表数量与 OEM

如果某一步失败（工具报"不可用"或返回空），跳过它继续，最后在报告里注明缺哪一项。

## 输出格式

用 Markdown 小标题，不要加装饰性分隔线。示例：

## 系统
- 厂商：<来自 SMBIOS>
- 型号：<来自 SMBIOS>
- BIOS：<厂商> <版本>

## 处理器
- 型号：<cpuid 的 brand string>
- 厂商：<cpuid 的 vendor>

## 内存
- 总容量：<dump_memmap 的 MB 数>

## 总线
每行一个设备，格式：`<bus:dev.func>  <VID:DID>  <类型>`

## 固件
- ACPI 表：<数量> 张，OEM <OEM id>

## 注意

- PCI 设备数量可能很多。只列每一类里的第一个，并说明"共 N 个设备"，不要逐个铺满整屏。
- 如果 SMBIOS 与 cpuid 的厂商不一致（虚拟机会这样），照实写出来，不要"修正"。
