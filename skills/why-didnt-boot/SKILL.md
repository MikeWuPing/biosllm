# 为什么进不了系统

biosllm 能运行，说明固件、CPU、内存、显示都是好的——**问题在固件之后的那一段**。
这台机器现在跑在固件里，而用户问的是"为什么没进系统"，所以排查对象是
**从固件交棒给操作系统的那一段**。

排查顺序是固定的：先看固件**打算**启动什么，再看那个东西**在不在**，最后看
**有没有东西挡住它**。三段里任意一段出问题，症状都是"起不来"。

## 第一步：固件打算启动什么

`read_env`，参数 `{"name":"Boot"}`

拿到 `BootOrder` 和所有 `Boot####`。`BootOrder` 是 4 位十六进制编号的序列，
**顺序就是尝试顺序**，第一位最先。

把 `BootOrder` 的第一位对上对应的 `Boot####`，那就是固件第一个要试的东西。
**先看这一个，不要一次看完所有启动项**——第一个失败才会试第二个，所以第一个
的名字和设备路径就是主嫌。

## 第二步：那个东西在不在

`Boot####` 现在会显示成「名字 + 设备路径」，形如：

    Boot0002 = "UEFI QEMU HARDDISK QM00001 " -> PciRoot(0x0)/Pci(0x1,0x1)/Ata(0x0)
    Boot0003 = "UEFI PXEv4 (MAC:525400123456)" -> PciRoot(0x0)/Pci(0x3,0x0)/MAC(...)/IPv4(...)

**路径的最后一段是设备，前面几段是到达它要走的路。** 按最后一段判断要查什么：

| 路径结尾 | 含义 | 接着查 |
|---|---|---|
| `Ata(...)` / `Sata(...)` / `Nvme(...)` | 一块磁盘 | `dump_disk` 看这块盘还在不在、能不能读 |
| `MAC(...)/IPv4(...)` | 网络启动（PXE） | `dump_net` 看网卡和链路 |
| `Fv(...)/FvFile(...)` | 固件内置项 | 这是固件自己的菜单项，失败通常是固件问题 |
| `Usb(...)` | U 盘 | `dump_usb` 看它枚举到没有，`dump_disk` 看容量对不对 |

**磁盘查不到的几种情况，结论完全不同**：

- **盘根本不在 `dump_disk` 里** → 物理连接或控制器问题。再看 `dump_pci`，
  路径里的 `Pci(...)` 那个控制器在不在——控制器不在，盘当然也不会在。
- **盘在，但型号读不出来** → 盘活着但有问题，通常是线缆或供电。
- **盘在且能读** → 问题不在硬件，往下看第三步。

**U 盘要按三步分开看**，因为三种情况的结论完全不同：

1. **`dump_usb` 里没有它** → 固件根本没枚举到这个设备。换口、换线，或看
   `dump_pci` 里 USB 控制器在不在。**这跟启动顺序无关，也跟安全启动无关。**
2. **`dump_usb` 里有，但接口列表里没有 `Mass Storage`** → 枚举到了，但不是
   可启动的存储设备（复合设备的一部分，或盘本身有问题）。
3. **有 Mass Storage 接口，但不在 `BootOrder` 里** → 盘是好的，固件只是
   没被要求试它。**这是"插了 U 盘也没用"最常见的原因**，要说清楚
   "不是 U 盘坏了，是启动顺序里没有它"。

顺序很重要：先确认枚举，再谈启动顺序，最后才轮到安全启动。跳过前两步就把
原因归到安全启动，是这类问题最常见的误判。

## 第三步：有没有东西挡住它

按这个顺序查，任一项命中就是答案：

1. **`read_env`，`{"name":"Secure"}`** —— `SecureBoot = 0x01` 表示安全启动已开启。
   开启时，**签名不被信任的引导程序会被拒绝**，而症状就是"找不到启动项"或
   "起一下又回来"。用户刚装的 Linux、自己做的 U 盘、改装机的引导器，都容易撞这一条。
2. **`read_env`，`{"name":"SetupMode"}`** —— `SetupMode = 0x01` 说明平台密钥可写，
   安全启动实际上形同虚设，这一项就不可能是原因。
3. **`read_env`，`{"name":"Boot"}` 里有没有 `BootNext`** —— `BootNext` 是一次性
  启动项，优先级高于 `BootOrder`。它在而目标设备不在，就会"每次都想启动一个不存在的东西"。
4. **`dump_memmap`** —— 内存容量小得可疑（比如 128 MB）会让引导器加载到一半失败。
   biosllm 能跑不代表内存够用。

## 怎么下结论

**只报工具查到的事实，不要猜。** 每一步的结论都要能指回具体的工具输出：

- 好的结论：「BootOrder 第一位是 Boot0002 → "UEFI QEMU HARDDISK"，指向
  `Ata(0x0)`；`dump_disk` 里没有这块盘，`dump_pci` 里也没有它路径上的
  `Pci(0x1,0x1)` 控制器。所以固件想启动的那块盘整条链都不在。」
- 坏的结论：「可能是硬盘坏了。」——没有指出是哪块盘、怎么判断的。

**查不到就说查不到。** 工具报"无匹配"、返回空、或说固件不支持，都是有效信息，
写进结论里。不要用常识补洞——这个技能的价值全在于它是这台机器的实测结果。

## 输出格式

## 固件想启动什么
`BootOrder` 第一位是什么，指向哪台设备。

## 那台设备在不在
`dump_disk` / `dump_pci` 的结果，以及它是否匹配路径。

## 有没有挡住它的
安全启动、SetupMode、BootNext、内存——逐项给查到的事实。

## 结论
两三句话。说清楚最可能的原因，以及**下一步该做什么**（进固件改启动顺序 /
换接口、关安全启动、检查线缆）。不要复述上面已经列出的内容。

## 什么时候承认不知道

如果三步都查完、每一样都对得上（盘在、控制器在、安全启动关着、内存正常），
那就是引导器本身或文件系统的问题，而 biosllm 的工具看不到那一层。**直接说
"硬件和启动配置都正常，问题在引导程序或文件系统，这需要另一套工具"**，
不要硬编一个原因。
