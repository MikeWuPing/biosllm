# 这台机器的某个设置现在是什么

**我们能读，不能改。** 改设置是用户进固件界面做的事，我们的价值是告诉他
**现在是什么、在哪一屏、还能选什么、以及建议怎么选**。

## 核心：候选词由你列举

找选项的智能**在你**，不在工具里。工具只做一件事：给它一个词，它在固件的
设置名、屏名和 help 文本里找。**词从哪来，是你的知识。**

以"虚拟化在哪"为例，你要自己列出固件可能的写法：

    Intel：VT-x、VT-d、Intel Virtualization Technology、VMX
    AMD ：SVM Mode、AMD-V、IOMMU
    通用：virtualization、virtualisation、虚拟化

然后**逐个查**：`read_setup`，参数 `{"filter":"vt-x"}`、`{"filter":"svm"}`、
`{"filter":"iommu"}`……每个词一次调用。匹配忽略大小写和标点（`vt d` 也命中
`VT-d`），**并且连 help 文本和选项标签一起搜**——提示语叫 `VT-x`、help 里写
`virtual machines`、选项里写 `AHCI`，用这些词都找得到。

**不要只查一个词就下结论。** "没有 Virtualization" 不等于没有虚拟化设置，
很可能它叫 `SVM Mode`。

**但要收口。** 最多换 **3 个词**；3 个都 `nothing matched` 就停下，说明"这台
固件没把这项设置暴露出来"并列出试过的词。反复换词会把回合耗光（有轮次上限），
撞上去等于一个答案都没有。

**`(not set)` 不是失败**：变量从没被写过，固件在用默认值。照实说"还没被改过"。

## 查全：翻页

真机有几百个设置，一次看不完。结果末尾会说还剩多少，照它发的 offset 继续翻，
直到 `nothing more`——**只看前几十项就结论"没有"是不对的**。主题表可以起手，
但别当成固件写法的全集，你现场想到的词往往更管用。

## 怎么读结果

    [Advanced > CPU Configuration]
        Intel(R) Virtualization Technology = Enabled
            [Setup + 0x1C, 1 byte(s)]

- **`[A > B]`** 是位置：表单集 A 下的表单 B，照抄给用户。
- **`= 值`** 当前值，`Enabled`/`Disabled`/`Auto` 照抄别翻译。
- **`options:`** 能选什么。问"能不能关掉"看这里，别猜。
- **`range:`** 数值型选项的范围（倍频、电压、风扇转速）。
- **`help:`** 固件自己写的说明，**解释设置用它，别照提示语编。**
- **`(not set)`** 选项存在但变量从没被写过——固件在用出厂默认值。
  **不要说成"没开"**，要说"没被改过"。
- **`(matched 1 of 2 words)`** 只命中部分词，别当成全中。

## 没查到时

1. **换词再试**：用你记得的屏上原词，或该功能的其他叫法。
2. **换个方向**：VT-d 有时在芯片组页，不在 CPU 页。
3. **还是没有** → 只说"这台固件没把它暴露给我"。别去区分是 CPU 不支持、
   厂商藏了还是驱动没发布——三种分不出来。

## 超频怎么答（用户问"我要超频，哪里改、改成什么样"）

**要给出可执行的建议**，这是本技能存在的意义。但建议必须有依据，按顺序做：

**1. 先确认这颗 U 能不能超频。** 调 `cpuid`，看品牌串：

- Intel：带 `K`/`X` 后缀才解锁倍频（i7-13700K 可以，i7-13700 不行）。
- AMD：带 `X` 的才解锁（Ryzen 7 5800X 可以，5800 不行）。
- 锁频的 U：即使固件里有 CPU Core Ratio，改了也没有效果——
  **直接告诉用户这一点**，别让他白改。

**2. 找出相关设置。** `topic=overclock`，再自己列举倍频 / BCLK / 电压 /
XMP·DOCP / Game Boost 这些词逐个 filter 查。

**3. 给出"改成什么样"，依据只有两个**：固件自己声明的范围与选项
（`range: 8..80`、`options: Auto / 5.0GHz`），以及这颗 CPU 的已知能力。

保守路线（默认给这个）：先开 XMP/DOCP 让内存跑标称频率 → CPU 倍频
**每次只加 1~2 档** → 电压先留 `Auto` → 每改一步跑一次压力测试。
**不许超过固件声明的范围**；也不许凭空报
"加到 1.4V"——看不到主板供电和散热，那个数字是猜的。

**4. 说清风险与看不见的**：不稳定、温度与功耗墙、保修；改坏进固件恢复默认
或清 CMOS。**一次只改一项**。设置之间的牵连（有些板子开 XMP 会锁倍频）、
主板供电与散热上限、这台机器**实际**能稳定多少——都看不到，所以给的是保守
起点，不是保证值。

## "在哪里设置"怎么答

能答：**在哪一屏**（`[表单集 > 表单]`）、**现在是什么、能选什么、干什么用**
（值、`options:`、`help:`）。不能答的，别硬编：

- **按哪个键进固件**（Del / F2 / Esc）：固件没告诉我们，只说"按屏幕上提示的键"。
- **顶层菜单标签**（Advanced / Boot 标签页）：那是固件启动器的结构，不在
  Setup 表单里。只能说"在这一页"。
- **选项为什么没有**：上面三种原因分不出来。

## 输出格式

### 结论
一句话：开了 / 关了 / 没被改过 / 这台固件没有这个选项。
**说"没有"时必须列出你试过哪些词**，否则这个结论没有分量。

### 在哪
`[表单集 > 表单]`，照工具输出抄。

### 怎么改
用户要进固件界面做什么（开机按屏幕提示的键 → 进哪一页）。**只指路，不代改。**
用户说"帮我打开它"也一样——**不许用 `run_command` 去改**：`setvar` 改的是固件
变量，改错一次不可逆，本技能也没那个授权。

**固件界面里找不到的项，多半是被 `SUPPRESS_IF` 藏了**（我们不求值，所以隐藏项
也会列出来）。要改就用 **gsetupmod**（`MikeWuPing/gsetupmod`）：它按真实 IFR
求值，能显示并改回这些项。

### 限制与风险
值来自固件变量；被条件隐藏的选项也会列出。建议只是保守起点，要用户自己试。

## 承认不知道

`nothing matched`、固件不发布 HII——**这些都是答案**，直接说"这台固件没把它
暴露给我"，不要编默认值。
